Break Before You Shape

Exact line breaking from a precompiled, certified width model

Draft · {{date}} · every number in this paper is read from result files produced on one Apple M3 machine

Abstract. Text engines shape a paragraph before they can break it into lines, because widths depend on kerning, ligatures and contextual forms. We show that, for the fonts and scripts we test, a line's shaped width is a local function of its text, and that this locality can be proven from a font's layout tables. We compile a shaper's behaviour into a small per-font model by measuring it as a black box, and a static analysis of OpenType and AAT tables certifies the lines on which the model is exact. Lines are then broken before anything is shaped. Across {{census_faces}} local font faces, {{census_certified:,}} certified lines contain no error. Inside Flutter, a {{=build_gzipBytes/1024:.0f}} KB (gzipped) file built once on the developer's machine reproduces Flutter's own line breaks and paragraph heights in {{mac_identical:,}} of {{=mac_identical+mac_different:,}} paragraph layouts ({{w_corpora}} corpora in {{w_languages}} languages written in Latin, Greek and Cyrillic, {{w_sizes}} font sizes, {{w_widths}} widths), and in every layout checked on an iOS simulator ({{ios_identical:,}}) and an Android emulator ({{android_identical:,}}). It hands {{mac_deferredPct:.2f}}% of layouts back to the engine and computes paragraph heights {{=min(t_docs_speedup_tp,t_chat_speedup_tp):.0f}}–{{=max(t_docs_speedup_tp,t_chat_speedup_tp):.0f}}× faster than TextPainter.

1 · Introduction

Every mainstream text stack (Chrome, WebKit, Android, Skia's SkParagraph, CoreText, DirectWrite) runs the same order: shape the paragraph with a shaper such as HarfBuzz, break it into lines using the shaped advances, and often reshape around the breaks. Shaping is the expensive step, and much of it is wasted. A chat list computing thousands of item heights, or an editor re-wrapping on every resize, shapes text that it never draws. Figure 1 shows the alternative this paper makes exact: break first, from a precompiled model, then shape only what is drawn.

Contributions.

  1. Distillation. A shaper is measured as a black box (every character, every pair, every ligature island in context) and compiled into exact tables. The model matches the target engine by construction.
  2. A certificate. A static analysis of OpenType (GSUB, GPOS, GDEF) and AAT (morx, kern, kerx) tables proves on which lines the model's width equals the shaped width.
  3. Break-first layout. Width-independent records give every candidate line's width in O(1), so a resize costs one greedy pass. Where the host engine's behaviour is uncertain, the breaker defers instead of guessing.
  4. Evidence. A census of {{census_faces}} font faces, and a Flutter implementation checked against Flutter's own layout on three platforms.

2 · Width is local, and can be distilled

A line's shaped width is the sum of its glyph advances plus positioning adjustments. In practice those adjustments are local: pair kerning touches two adjacent glyphs, and a ligature replaces a short run of letters. So the width of any line decomposes into a few kinds of terms: one advance per character, one term per adjacent pair, and a term for each ligature island with its two neighbours. Figure 2 shows a real decomposition, measured from Flutter.

Distillation. We do not parse kerning or ligature tables. We ask the target shaper. For Flutter, the oracle is Flutter's own ui.Paragraph, run under flutter_tester on the developer's machine:

  • every character alone;
  • every ordered pair;
  • every certificate island alone, and next to every safe neighbour (§3).
We measure at a font size equal to the font's units per em, so values are font units. All {{build_layouts:,}} measurements came back as exact integers, and widths scale linearly with size (§5.5), so one file serves every size. For Roboto (Latin, Greek and Cyrillic, {{build_characters}} characters), identical rows and columns of the pair matrix collapse into {{build_pair_classes}} classes. With {{build_islands}} islands, the file is {{=build_bytes/1024:.0f}} KB, {{=build_gzipBytes/1024:.1f}} KB gzipped, and builds in {{=build_buildMs/1000:.1f}} s.

3 · A certificate from the font's tables

Locality is not guaranteed: a contextual substitution can make a glyph depend on text arbitrarily far away. So each character is classified from the font's layout tables, without running the shaper:

  • S (safe): no substitution can change or consume its glyph;
  • P (primer): it can start a substitution, such as the first letter of a ligature;
  • K (passive): it can only be consumed by a substitution a primer started;
  • U (unsafe): everything else.

An island is a maximal run of P/K characters that contains a primer.

Theorem. Let a line contain no U character, and let every island in it have at most m characters. Then the shaped width of the line equals the model's width.

Proof sketch.

  1. Substitution leaves S glyphs untouched, and islands are closed.
    • OpenType. A single, multiple or alternate lookup fires only at its coverage glyphs, which are U. A contextual rule fires only if every position matches a glyph that can occur, so for each live rule the cheapest position's characters are made U. Ligatures start at P and consume only P/K glyphs.
    • AAT. Action reachability is computed over the alphabet; subtables that cannot act are the identity. In the rest, S classes return every reachable state to a start state with no substitution, the start states agree, end of text has no effect after an island, and a bounded exhaustive check shows no action inside an island reaches state stored before it.
  2. Positioning is pair-additive. Only single adjustments, PairPos with ValueFormat2 = 0, and kern or kerx pair formats can fire.
  3. Width splits into local terms. By 1 and 2, the width is a sum of terms, each touching at most one island and its S neighbours.
  4. The terms agree. The model's terms are measured values of exactly those terms. Islands are measured with every S neighbour, and the checker verifies no model term spans two islands. ∎

The proof trusts that the shaper implements OpenType and AAT as specified, that fontTools parses the tables correctly, and the analyzer's code, which is tested but not machine-checked. By default it also trusts that the shaper selects lookups as HarfBuzz does (script, language, default variation coordinates); a strict mode drops that assumption.

4 · Breaking before shaping, the way the host does

For each paragraph, one pass builds a width prefix in units, and a second finds break opportunities. Both are independent of the box width, so re-wrapping at a new width only re-runs the greedy pass over these records. To reproduce a specific engine, the breaker must also reproduce that engine's conventions. We measured Flutter's rather than assuming them (Table 1), and the breaker defers whenever a decision depends on something it cannot certify.

All methods run on the same paragraphs, the ones break-first decides itself, at {{t_docs_size:g}} px.   • Paragraph heights: break-first is {{t_docs_speedup_tp:.1f}}× (docs) and {{t_chat_speedup_tp:.1f}}× (chat) faster than TextPainter.

5.5 · Font sizes and float drift

Flutter's widths are linear in font size, so one file in font units serves every size. But SkParagraph accumulates positions across a paragraph in float32.

  • Exact sizes ({{drift_exact_sizes}} px for Roboto): size/units-per-em is a short binary fraction and positions are exact.
  • Other sizes: positions drift by up to {{drift_max_rel:.1e}} of the x position, as much as {{drift_max_abs:.2f}} px on a paragraph-long line.

The breaker certifies exact sizes outright. At other sizes it defers any decision that a width error of 2 × {{drift_margin:.1e}} of the x position could flip: drift at both ends of the line, each allowed {{=drift_margin/drift_max_rel:.1f}}× the largest drift measured. On Android the engine also truncates the font size to 1/{{android_size_quantum}} px, which a single start-up probe detects. With both measures, all {{=len(mac_sizes)}} sizes in Table 2 had zero mismatches on every platform.

6 · Related work

  • TeX's TFM lig/kern programs are a hand-made per-font width automaton: the closest ancestor of the model, without contextual forms or a certificate.
  • PDF libraries sum AFM widths and kerning pairs, ignoring substitution.
  • WebKit's simple text path skips the shaper only when kerning and ligatures are off.
  • Android's Minikin and Pretext measure and cache words, which loses context across words (§5.2).
  • HarfBuzz's UNSAFE_TO_CONCAT makes reshaping after breaking cheaper, but keeps the shape-first order.
  • typeset (2026) computes widths from advances and pair kerning with a HarfBuzz fallback, without contextual terms or a proof.

We found no prior static analysis of shaping tables. This survey is a web search, not an exhaustive review.

7 · Limitations

  • Scripts. Latin, Greek and Cyrillic only; Arabic joining and Indic syllables are future work. Only plain, single-style, left-to-right paragraphs are covered.
  • Fonts. The Flutter evaluation uses one font (Roboto); the census covers the faces installed on one Mac.
  • Proof. The certificate relies on the trust base in §3, and the AAT analysis rejects reversed contextual subtables, rearrangement, insertion and kerx state machines rather than analysing them.
  • Measurement. Mobile timings come from an emulator, not a phone.
  • Scope of the gain. The speedup is for measurement and line breaking; painting is unchanged, and lines that are drawn are still shaped.
