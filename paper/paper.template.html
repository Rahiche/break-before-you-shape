Break Before You Shape

Exact line breaking from a precompiled, certified width model

Raouf Rahiche · Version 1.0 · {{date}} · github.com/Rahiche/break-before-you-shape
Every number in this paper is read from result files produced on one Apple M3 machine and on GitHub Actions.

Abstract. Text engines shape a paragraph before they can break it into lines, because widths depend on kerning, ligatures and contextual forms. We show that, for the fonts and scripts we test, a line's shaped width is a local function of its text, and that this locality can be proven from a font's layout tables. We compile a shaper's behaviour into a small per-font model by measuring it as a black box, and a static analysis of OpenType and AAT tables certifies the lines on which the model is exact. Lines are then broken before anything is shaped. Across {{census_faces}} local font faces, {{census_certified:,}} certified lines ({{census_certified_share:.0f}}% of all) contain no error. Inside Flutter, a {{=build_gzipBytes/1024:.0f}} KB (gzipped) file built once on the developer's machine reproduces Flutter's own line breaks and paragraph heights in {{mac_identical:,}} of {{=mac_identical+mac_different:,}} paragraph layouts on macOS ({{w_corpora}} corpora in {{w_languages}} languages, {{w_sizes}} font sizes, {{w_widths}} widths), and in all {{ci_identical:,}} it decides on Linux, macOS, an iOS simulator and an Android emulator in continuous integration. The same holds with letter and word spacing, height multipliers, maxLines and hard line breaks ({{styles_identical:,}} layouts), for Hebrew, mixed-direction, Arabic, Japanese, Chinese and Korean text in four more fonts ({{scripts_identical:,}} layouts), and in {{beyond_rows}} further checks ({{beyond_identical:,}} layouts) covering struts, font features, rich text, bundled fallback fonts, combining marks, pointed Hebrew, vowelled and letter-spaced Arabic, emoji, and Indic scripts. Text a sidecar does not cover but the device's own fonts do (emoji, Brahmic scripts) is measured once per run through Flutter, which is exact because a change of font is a change of shaping run. Not one layout differs. The breaker hands {{mac_deferredPct:.2f}}% of Latin-script layouts back to the engine and computes paragraph heights {{=min(t_docs_speedup_tp,t_chat_speedup_tp):.0f}}–{{=max(t_docs_speedup_tp,t_chat_speedup_tp):.0f}}× faster than TextPainter.

1 · Introduction

Every mainstream text stack (Chrome, WebKit, Android, Skia's SkParagraph, CoreText, DirectWrite) runs the same order: shape the paragraph with a shaper such as HarfBuzz, break it into lines using the shaped advances, and often reshape around the breaks. Shaping is the expensive step, and much of it is wasted. A chat list computing thousands of item heights, or an editor re-wrapping on every resize, shapes text that it never draws. Figure 1 shows the alternative this paper makes exact: break first, from a precompiled model, then shape only what is drawn.

Contributions.

  1. Distillation. A shaper is measured as a black box (every character, every pair, every ligature island in context) and compiled into exact tables. The model matches the target engine by construction.
  2. A certificate. A static analysis of OpenType (GSUB, GPOS, GDEF) and AAT (morx, kern, kerx, state machines included) tables proves on which lines the model's width equals the shaped width: Arabic letters per joining form, features the app turns on, and combining marks with the compositions HarfBuzz makes.
  3. Break-first layout. Width-independent records give every candidate line's width in O(1), so a resize costs one greedy pass. The breaker reproduces the host's measured conventions (spacing, line heights, struts, hard breaks, bidirectional runs, split kerning, shaping runs across fonts) and defers wherever the host's behaviour is uncertain.
  4. Evidence. A census of {{census_faces}} font faces, and a Flutter package checked against Flutter's own layout on four platforms, for plain and rich text in Latin, Greek, Cyrillic, Hebrew, Arabic, Chinese, Japanese, Korean and Indic scripts and with emoji.

2 · Width is local, and can be distilled

A line's shaped width is the sum of its glyph advances plus positioning adjustments. In practice those adjustments are local: pair kerning touches two adjacent glyphs, and a ligature replaces a short run of letters. So the width of any line decomposes into a few kinds of terms: one advance per character, one term per adjacent pair, and a term for each ligature island with its two neighbours. Figure 2 shows a real decomposition, measured from Flutter.

Distillation. We do not parse kerning or ligature tables. We ask the target shaper. For Flutter, the oracle is Flutter's own ui.Paragraph, run under flutter_tester on the developer's machine:

  • every character alone;
  • every ordered pair;
  • every certificate island alone, and next to every safe neighbour (§3).
We measure at a font size equal to the font's units per em, so values are font units. All {{build_layouts:,}} measurements came back as exact integers, and widths scale linearly with size (§5.5), so one file serves every size. For Roboto (Latin, Greek and Cyrillic, {{build_characters}} characters), identical rows and columns of the pair matrix collapse into {{build_pair_classes}} classes. With {{build_islands}} islands, the file is {{=build_bytes/1024:.0f}} KB, {{=build_gzipBytes/1024:.1f}} KB gzipped, and builds in {{=build_buildMs/1000:.1f}} s.

3 · A certificate from the font's tables

Locality is not guaranteed: a contextual substitution can make a glyph depend on text arbitrarily far away. So each character is classified from the font's layout tables, without running the shaper:

  • S (safe): no substitution can change or consume its glyph;
  • P (primer): it can start a substitution, such as the first letter of a ligature;
  • K (passive): it can only be consumed by a substitution a primer started;
  • U (unsafe): everything else.

An island is a maximal run of P/K characters that contains a primer.

Theorem. Let a line contain no U character, and let every island in it have at most m characters. Then the shaped width of the line equals the model's width.

Proof sketch.

  1. Substitution leaves S glyphs untouched, and islands are closed.
    • OpenType. A single, multiple or alternate lookup fires only at its coverage glyphs, which are U. A contextual rule fires only if every position matches a glyph that can occur, so for each live rule the cheapest position's characters are made U. Ligatures start at P and consume only P/K glyphs.
    • AAT. Every morx subtable (rearrangement, contextual, ligature, insertion, in either processing order) and the kerx/kern state machines are emulated as HarfBuzz runs them. An S class changes nothing from any reachable state and returns to a state equivalent to a start state (state minimisation). Every island up to the bound runs through the whole chain from each start state, with every mark and stack entry from before it stale; if it touches stale state or depends on its surroundings, its cheapest character becomes U.
  2. Positioning is pair-additive. Only single adjustments, PairPos with ValueFormat2 = 0, the kern and kerx pair formats, and kerning machines proven local by step 1 can fire.
  3. Width splits into local terms. By 1 and 2, the width is a sum of terms, each touching at most one island and its S neighbours.
  4. The terms agree. The model's terms are measured values of exactly those terms. Islands are measured with every S neighbour, and the checker verifies no model term spans two islands. ∎

The proof trusts that the shaper implements OpenType and AAT as specified, that fontTools parses the tables correctly, and the analyzer's code, which is tested but not machine-checked; its AAT emulation was compared with hb-shape on about 22,700 islands. By default it also trusts that the shaper selects lookups as HarfBuzz does (the scripts certified, language, default variation coordinates); a strict mode drops that assumption.

Two additions for the breaker. Pair roles: for each character, whether its glyph can be the first or second glyph of any pair adjustment (GPOS pair and cursive coverage, kern pairs; anything not analysed counts as every glyph). Only first × second pairs are measured, so a CJK font with {{cjk_hiragino_chars:,}} characters needs no pair table at all and one with {{cjk_sdgothic_chars:,}} builds in under a second. Joining forms: each Arabic (letter, form) is certified as a virtual character whose glyph is the font's isol, init, medi or fina substitute; the breaker picks forms from Unicode joining types, as HarfBuzz's Arabic shaper does, so lam-alef is just an island.

Substitutions and marks. A single substitution that a feature applies to every glyph it covers fixes a character's glyph wherever it stands, so it is part of the character, not a hazard: the analysis follows each character through all of them (small caps, oldstyle figures, stylistic sets). Combining marks get a class of their own, M. HarfBuzz composes a base and a following mark into the precomposed character before any lookup runs, when the font has it, and zeroes the advance of every GDEF mark after positioning. So the certificate lists the font's compositions and, for each mark, its combining class and whether kerning skips it or stops at it (from lookup flags); a rule that can fire only on a mark left uncomposed next to certain characters becomes an exclusion the breaker checks, and a context rule whose nested lookups only move or swap marks cannot change a width at all.

4 · Breaking before shaping, the way the host does

For each paragraph, one pass builds a width prefix in units, and a second finds break opportunities. Both are independent of the box width, so re-wrapping at a new width only re-runs the greedy pass over these records. To reproduce a specific engine, the breaker must also reproduce that engine's conventions. We measured Flutter's rather than assuming them (Table 1), and the breaker defers whenever a decision depends on something it cannot certify.

5.1 · Census: how often does the certificate apply?

We ran the analyzer and the checker on every font face on the machine that covers basic Latin ({{census_faces}} faces). For each, the checker compares every certified line of a {{census_paragraphs:,}}-paragraph English corpus sample at {{w_census_widths}} widths against HarfBuzz, using exact ground truth that reshapes every candidate line.

  • Errors: {{census_certified:,}} of {{census_lines:,}} lines ({{census_certified_share:.1f}}%) were certified, and {{census_wrong}} were wrong.
  • Coverage: {{census_ge99}} faces certify at least 99% of their lines; {{census_zero}} certify none.
  • Causes of failure ({{census_low}} faces under 99%, Figure 4b): in {{census_low_subst}} the font's substitutions genuinely touch common letters; {{census_low_aat}} have AAT contextual or ligature machines over common letters that are not local (Apple Chancery, Marion, Aqua Kana); in {{census_low_island}} the exhaustive island check's budget lowered the island bound below 4; the rest lack characters or class letters as marks.

5.2 · Today's shortcuts are not exact

The usual alternatives to full reshaping lose context, and the error is measurable. Against exact ground truth in HarfBuzz ({{c_fonts}} fonts, {{c_paragraphs:,}} paragraphs, {{c_widths}} widths; Zapfino is left out, because its long contextual swashes are exactly what the certificate hands back to the shaper):

  • Shape once, then break (what SkParagraph does) gets up to {{=100-c_shapefirst_min:.1f}}% of paragraphs wrong.
  • Per-word caches (Minikin, Pretext) get up to {{=100-c_wordcache_min:.1f}}% wrong.
  • The distilled model gets {{=100-c_breakfirst_min:.1f}}% wrong.

  • On GitHub's machines (median of 3 runs; one on Android): {{ci_macos_docs_speedup:.1f}}× / {{ci_macos_chat_speedup:.1f}}× on a virtual M1, {{ci_linux_docs_speedup:.1f}}× / {{ci_linux_chat_speedup:.1f}}× on Linux, and {{ci_android_docs_speedup:.1f}}× / {{ci_android_chat_speedup:.1f}}× on the Android emulator (docs / chat).

5.7 · Font sizes and float drift

Flutter's widths are linear in font size, so one file in font units serves every size. But SkParagraph accumulates positions across a paragraph in float32.

  • Exact sizes ({{drift_exact_sizes}} px for Roboto): size/units-per-em is a short binary fraction and positions are exact.
  • Other sizes: positions drift by up to {{drift_max_rel:.1e}} of the x position, as much as {{drift_max_abs:.2f}} px on a paragraph-long line.

The breaker certifies exact sizes outright. At other sizes it defers any decision that a width error of 2 × {{drift_margin:.1e}} of the x position could flip: drift at both ends of the line, each allowed {{=drift_margin/drift_max_rel:.1f}}× the largest drift measured. On Android the engine also truncates the font size to 1/{{android_size_quantum}} px, which a single start-up probe detects. With both measures, all {{=len(mac_sizes)}} sizes in Table 2 had zero mismatches on every platform.

6 · Related work

  • TeX's TFM lig/kern programs are a hand-made per-font width automaton: the closest ancestor of the model, without contextual forms or a certificate.
  • PDF libraries sum AFM widths and kerning pairs, ignoring substitution.
  • WebKit's simple text path skips the shaper only when kerning and ligatures are off.
  • Android's Minikin and Pretext measure and cache words, which loses context across words (§5.2).
  • HarfBuzz's UNSAFE_TO_CONCAT makes reshaping after breaking cheaper, but keeps the shape-first order.
  • typeset (2026) computes widths from advances and pair kerning with a HarfBuzz fallback, without contextual terms or a proof.

We found no prior static analysis of shaping tables. This survey is a web search, not an exhaustive review.

7 · Limitations

Everything outside this list is decided exactly or handed to Flutter; what is listed is handed to Flutter or not claimed.

  • Scripts. Indic syllables (reordering), Thai, Lao, Khmer and Burmese (dictionary line breaking), vowel and other combining marks, emoji, and letter-spaced Arabic go to Flutter, as does any character a font lacks (fallback fonts differ between devices).
  • Styles. A paragraph has one font and size: rich text with several, font features and strutStyle go to Flutter.
  • Proof. The trust base in §3; the AAT emulation follows HarfBuzz 15 and is tested, not proven. Fonts with only a mort table, rare kerx/kern formats, and islands beyond the stated bounds are blocked rather than analysed.
  • Measurement. Mobile timings come from simulators and emulators, not phones.
  • Scope of the gain. The speedup is for measurement and line breaking; painting is unchanged, and lines that are drawn are still shaped.
